Fade Shader Plates

Twelve plates, varyings to gl_FragColor. The vertex shader built a ribbon tall enough to hold ±2σ of every column. This shader carves the density out of that envelope with one Gaussian, and it does so with no anti-aliasing whatsoever — a fact worth understanding before the half-pixel columns arrive.

Volume II. Volume I — Range Shader Vector Plates — ends where this begins.

PLATE 01

What crosses the boundary

Five varyings and two uniforms are everything the fragment shader gets. It never sees a texture, a sample, or an id.

varying vec4  fragColor;
varying float normThickness;
varying vec3  statsLeft, statsRight,
              statsPrevRight, statsNextLeft;

Each vec3 is packed (avg, sdev, nanFlag) at range-vert.glsl:233-237. The one thing to hold on to is that everything is a fraction of viewport height:

// vertex: normalised by ampRange
sdev = statsCurr.y / ampRange;
avg  = deamp(avg, amplitude);
normThickness = thickness/viewport.w;

// fragment: the same ruler
y = (gl_FragCoord.y - viewport.y)
    / viewport.w;
dist, sdev and halfThickness all live in that one unit. That is why dist/sdev is a pure number, and why the Gaussian needs no scale factor anywhere.

The handoff. Geometry was volume I's subject; alpha is this one's. float x is computed at line 34 and never read — the only dead line in the file.

PLATE 02

Four vertices, two positions

The buffer pushes four vertices per id. But look at what gl_Position actually consumes:

position = vec2(pxStep*(id+.5)/vw,
                avgCurr);
position += sign * join * .5
            * thickness / viewport.zw;

side appears nowhere in that chain. It is read only at lines 238–241, where it swings which neighbours land in the varyings. So the four vertices of a column collapse onto two points — and not approximately: the arithmetic is bit-identical, so they are exactly coincident.

Two coincident vertices is the definition of a degenerate triangle. Everything in the next plate follows from this one fact.
side = −1side = +1same point

PLATE 03

Two of every four triangles are degenerate

A triangle strip emits tri_k = (v_k, v_k+1, v_k+2) for every k. Walk the strip and classify each triangle by whether any two of its vertices share a position. The pattern has period four — D D R R — so exactly half the triangles have zero area.

It is tempting to sample a six-triangle window and conclude four-in-six. That window straddles two degenerate runs and over-counts them; the steady-state rate is the period-4 pattern below. For n columns: 4n vertices, 4n−2 triangles, 2n degenerate.

Degenerate triangles are drawn as the line segments they collapse to. They are emitted, clipped, and discarded before rasterisation — vertex cost, zero fragment cost.

Generated by walking the strip, not transcribed. Position is written symbolically: x2,T is column 2's top vertex. A triangle is degenerate when any two of its three positions are equal.

PLATE 04

Everything lined up

Attributes on the left, vertex-shader outputs on the right, one row per vertex. sn abbreviates the stats triple for column n. The varying columns are evaluated straight from the source:

statsRight     = side < 0. ? statsCurr  : statsNext;
statsLeft      = side < 0. ? statsPrev  : statsCurr;
statsPrevRight = side < 0. ? statsPrev2 : statsPrev;
statsNextLeft  = side < 0. ? statsNext  : statsNext2;

The highlighted band is one real quad — the two side=+1 vertices of column 0 and the two side=−1 vertices of column 1. Read the four varying columns down that band: every row is identical. (s0, s1, s−1, s2), four times.

That is the whole purpose of side. A varying that is equal at every corner interpolates to that same value everywhere inside — so the stats arrive at the fragment shader flat, with no gradient. GLSL ES 1.00 has no flat qualifier; this is how you get one anyway. The price is double the vertices and half the triangles thrown away.

Note also what the quad carries: columns −1, 0, 1 and 2. A four-wide window, from a two-wide quad. Plate 10 is where that extra reach earns its keep.

Rows 2–5 shaded: the four vertices of the quad spanning columns 0→1. Degenerate-triangle vertices are not excluded from the table — every vertex is shaded regardless of what triangle consumes it.

PLATE 05

A Gaussian used as opacity

Set aside the statistics for a moment. The shape is

alpha = exp(−½ · (d/σ)²)

a bell that is 1.0 at d = 0 and falls away. σ is not a height — it is the horizontal ruler. Distances only ever enter as d/σ, so the curve has exactly one shape; σ stretches it.

The landmarks are worth memorising, because they are the same three numbers for every σ:

d = 1σ  →  alpha = 0.607
d = 2σ  →  alpha = 0.135
d = 3σ  →  alpha = 0.011

The meaning in this shader: d is how far a pixel sits from its column's mean, and σ is that column's standard deviation. So opacity tracks how likely a sample from that column landed at this height. Dense where the samples cluster, transparent in the tails.

This is not a filter in the signal-processing sense despite the name. Nothing is convolved. It is a density ramp evaluated per fragment.

Drag σ. The curve's shape never changes — only the ruler beneath it. The three landmark heights are fixed for all σ.

PLATE 06

The pdf() scaffolding cancels

The source does not write that exp. It builds a true probability density — the kind that integrates to 1 — and then divides it by its own peak:

pdf(x,m,v) = exp(−½(x−m)²/v)
             / sqrt(TAU*v);

pdfCoef = pdf(0., 0., σ²);
  // = 1 / sqrt(TAU*σ²)
dist = pdf(dist, 0., σ²) / pdfCoef;

The sqrt(2πσ²) is in the numerator and the denominator. It cancels exactly, leaving the bare exp from Plate 05. Two exp, two sqrt, a pow and a divide, to compute one exp.

It is not a bug — the result is right. But it obscures the intent, and it explains the comment // pdfCoef makes sure pdf is normalized: the author wanted a peak of 1, not an area of 1, and got there the long way.

The σ = 0 branch is a Dirac delta: variance == 0. returns x == mean ? 9999. : 0. Both numerator and denominator hit 9999 when d = 0, so the ratio is 1 — and 0 everywhere else. 9999 is standing in for infinity, and it cancels the same way.

Top: the raw pdf, whose peak changes with σ — unusable as opacity. Bottom: after dividing by pdfCoef. Same three curves, all peaking at 1.

PLATE 07

The envelope and the fill

This is the thesis of both volumes. Volume I derived

vertSdev = 2. * sdev
           * viewport.w / thickness;

and used it to make the ribbon tall enough to hold ±2σ. That is geometry, and geometry is binary — a pixel is inside the quad or it is not.

This shader supplies what geometry cannot: how much of the column's mass is at each height inside that envelope. The quad is the container; the Gaussian is the contents.

Which is also why 2σ and not 1σ or 3σ. At 2σ the alpha has already fallen to 0.135 — dim enough that the quad's hard edge is nearly invisible. Size it to 1σ and you would clip the ribbon at alpha 0.607, a plainly visible cut. Size it to 3σ and you would pay for a band of near-zero pixels.

quad edge (±2σ)alphaavg

Three columns of differing σ. The envelope tracks σ because the vertex shader made it; the fill tracks σ because this shader does. Both are the same number.

PLATE 08

Four blocks that cannot both fire

The body is four if blocks — above/below × right/left — each one gl_FragColor.a *= fade(...). They are sequential, not else if, so they read as though a fragment could be multiplied four times.

It cannot. Take blocks 1 and 2:

// block 1
y > avgRight + ht && avgRight > avgLeft
// block 2
y > avgLeft  + ht && avgLeft > avgRight

The second conditions are negations of each other. Every other pairing contradicts either on the y comparison or on the avg ordering — blocks 1 and 3 need y both above and below the same centre; 2 and 3 need y > avgLeft+ht and y < avgRight−ht with avgLeft > avgRight, which is empty. At most one block runs.

What the nesting decides is whose Gaussian to use. A column that is a local maximum owns the pixels above it. A column that is not defers to the taller neighbour — whose quad also covers this pixel, and whose distribution is the honest one there.

This is why the varyings reach four columns wide. Deciding "am I a local max" needs a neighbour on each side, and the deferral then needs that neighbour's stats in hand.

The pixel marked ◆ sits above both centrelines. Left column is the taller, so block 2 claims it and fades against statsLeft; blocks 1, 3 and 4 are all excluded by their guards.

PLATE 09

There is no anti-aliasing

Not reduced, not cheap — absent. No smoothstep. No fwidth or dFdx (OES_standard_derivatives is never enabled). No discard. No antialias on the context. Coverage is never computed.

The consequence is at the band edge. Inside ±halfThickness the fragment keeps full alpha, untouched. One pixel outside, fade() takes over — but it does not resume at 1.0. It resumes at

exp(−½ · (halfThickness/σ)²)

which is a step discontinuity. When σ ≈ halfThickness that is a drop to 0.607 across one pixel boundary; you can see it.

The outer falloff is the opposite case, and it is where the shader gets away with it: the Gaussian reaches ~0 well before the quad's own edge, so the geometric silhouette is never visible. That is not anti-aliasing — it is a hard edge hidden under a value that happens to be near zero. Move σ up until 2σ exceeds the quad and the edge reappears.

Alpha along a vertical cut through one column. The flat top is the untouched band; the drop at ±ht is the discontinuity. Watch it grow as σ shrinks.

PLATE 10

Half-pixel columns are the normal case

Not an edge case. index.js:547:

pxStep = Math.max(
  viewport[2] / span,
  this.pxStep || .5
);
// pxStep affects jittering on
// panning, .5 is good value

Whenever the data is wider than twice the viewport, columns are half a pixel wide — and that is exactly the regime where the range shader is selected (pxPerSample <= 1, line 684).

A fragment exists only if a pixel's centre is covered. With two quads per pixel, one wins and one is never shaded. At exactly 0.5 the arithmetic is stark: pixel p's centre is p+0.5, so it lands in column 2p+1. Every even column is dropped, always. Deterministic decimation, not noise.

The saving grace is Plate 04. The surviving quad's varyings are flat and span columns i−1…i+2, so the discarded column's stats still reach the fragment shader — as a neighbour. The mean you see is sampled at half rate; the envelope is not.

And the comment now reads differently. At exactly 0.5, centres land precisely on column boundaries, so which column wins is decided by the fill rule — and panning slides that phase. Locking to 0.5 makes the decimation phase stable instead of a slowly crawling moiré. That is a reading of the author's intent, not a claim from the source.

Top band: columns as the vertex shader emits them. Dots: pixel centres. Bottom band: which column each pixel actually samples. Greyed columns produce no fragment anywhere.

PLATE 11

Is it run more than once per pixel?

Yes — but from overdraw, not from multisampling.

depth.enable = false, nothing is discarded, and blending is on. So every triangle covering a pixel shades it and composites. Sheared quads at steep joins overlap in x; the multipass overlay redraws the same geometry shifted by passId. Each of those is another full invocation.

The blend function is the interesting part:

srcRGB   : src alpha
dstRGB   : one minus src alpha
srcAlpha : one minus dst alpha
dstAlpha : one

That alpha row is a union, not a sum: a' = a + a(1−a). Two coincident fragments at α = 0.5 give 0.75, not 1.0. It saturates toward 1 and never exceeds it. That is the closest thing to coverage integration in the pipeline — and it is an approximation, not a box filter.

MSAA would not change any of this. The fragment shader runs once per pixel and the result is broadcast to every covered sample; only coverage is evaluated per-sample. y > avg + halfThickness is still tested at one point. MSAA smooths the quad's silhouette — the one edge already hidden by the falloff — and does nothing for the band discontinuity of Plate 09.

Derivative helper invocations do not apply either; with no fwidth, there is no 2×2 quad to co-execute. And the degenerate triangles of Plate 03 cost vertex work but produce zero fragments.

Union versus sum, over repeated coincident fragments. The dashed line is what a true coverage sum would do; the solid curve is what this blend does.

Edges of the reading

dead code

The unused fragment x

float x = (gl_FragCoord.x - viewport.x) / viewport.z; at line 34 is computed and never read. Harmless — the compiler drops it — but it hints at an earlier version that varied alpha horizontally as well as vertically.

redundancy

Two pdfs where one exp would do

Per Plate 06 the normalisation cancels identically. Writing exp(-.5*d*d/(sdev*sdev)) is the same number in one instruction, and states the intent. The pdf() helper would then have no callers.

artifact

The band edge is discontinuous

Alpha jumps from 1.0 to exp(−½(ht/σ)²) at ±halfThickness. A smoothstep over one fwidth would close it, at the cost of requiring the derivatives extension.

sampling

Half the columns never rasterise

At the default pxStep = 0.5 every even column is dropped by pixel-centre coverage. The four-wide varying window softens this for the envelope but not for the mean itself.

nuance

The nan flag short-circuits everything

fade() returns 0 the moment stats.z == -1., before any arithmetic. Gaps in the data punch fully transparent holes rather than fading — the only place in the file where alpha is set rather than multiplied toward.

nuance

σ = 0 makes the fade a hard gate

The Dirac branch returns 1 only where d == 0 exactly. But fade() is only ever called from outside the band, where d > halfThickness > 0 — so a zero-variance column contributes nothing above or below its band. Correct, and reachable only by that reasoning.

context

Volume I's join limit is this shader's premise

The three-way branch existed to make the ribbon exactly 2σ tall. If you changed that constant you would have to retune nothing here — the Gaussian adapts — but the hidden outer edge of Plate 09 would stop being hidden.

counting

Two in four, not four in six

The degenerate fraction is exactly one half in steady state. A six-triangle window that begins and ends on a degenerate run reports 4/6; the period-4 pattern D D R R is the real rate. Plate 03 walks it rather than sampling it.
