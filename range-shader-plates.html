Range Shader Vector Plates

Ten plates, attributes to gl_Position. Every vector in the range shader is built in one space and measured against one ruler — half the line thickness. Once you see that ruler, the three-way join branch stops being three cases and becomes one continuous curve.

fixed for every plate: viewport 660 × 220 px thickness 24 px pxStep 85 px avgPrev 0.22 avgCurr 0.72 avgNext 0.40
PLATE 01

Three attributes, four vertices, one column

The vertex buffer is built once and never changes. For each id it pushes four vertices — and the source comment draws them as a zigzag strip:

x.push(i, 1, -1,  i, -1, -1)
x.push(i, 1,  1,  i, -1,  1)
//    id  sign  side

id picks the time bucket — one column of the waveform. sign is ±1 and picks the top or bottom edge of the ribbon. side is ±1 and does not move the vertex at all: it only swings which neighbours land in the varyings statsLeft/statsRight for the fragment shader to antialias against.

So position depends on id and sign only. The whole rest of this document is one question: given id, how far and in what direction does sign push?

Triangle-strip order. Both side values sit at the identical point — drawn split apart here only to be countable.

PLATE 02

One id becomes a mean and a spread

offset = id * sampleStep names the centre of a window sampleStep samples wide. The textures hold running sums of x and x², so both moments are two texture reads and a subtract:

// s0, s1 = window end samples
float n   = offset1l - offset0l;
float avg = (s1.y - s0.y) / n;
float mx2 = (s1.z - s0.z) / n;
// σ(x)² = M(x²) − M(x)²
float sdev =
  sqrt(abs(mx2 - avg*avg));

That is the whole reason this shader differs from line-vert.glsl. The plain line shader plots one sample and hardcodes sdev = 0. This one plots an aggregate, and an aggregate has a width as well as a height.

avg± 1 σwindow

The .w channel carries a NaN flag; −1 means “no data here” and drives the two end-cap branches in Plate 09.

PLATE 03

Five taps, then the skeleton

stats() is called five times — at offset and at ±1, ±2 sampleStep. deamp (really reamp) rescales each mean out of the amplitude range into 0…1, which is the space everything from here on lives in:

return (v - amp.x) / (amp.y - amp.x);

Then the vertex's home point, before any thickness is applied:

vec2 position = vec2(
  pxStep * (id + .5) / viewport.z,
  avgCurr
);

The +.5 centres the vertex in its pixel column rather than on its left edge. Divide by viewport.z and x is 0…1 too. This polyline is the skeleton; the remaining plates only decide how to give it width.

Only the middle three points build the join. prev2 and next2 exist purely to fill varyings for the fragment shader.

PLATE 04

The rotation that is never written down

A segment runs d = (dx, dy). Its perpendicular is (−dy, dx). The shader never forms d — it writes the rotated components straight out:

vec2 normalLeft = normalize(vec2(
  -(avgCurr - avgPrev),   // −dy
  pxStep / viewport.w     // +dx
));

Both components are in the same unit — fractions of viewport height — so this is a true perpendicular in isotropic pixel space, not a stretched one.

And here is your −90°…+90°: pxStep is always positive, so n.y is always positive. Every normal in this shader lives in the upper half-plane. Flat segment → straight up. Steep segment → nearly horizontal. It can never point down, because time never runs backwards.

Right: the reachable fan. The opening angle is set by pxStep/viewport.w versus the sample-to-sample jump.

PLATE 05

What a join actually has to satisfy

Two segments meet at the vertex. Each one, given width, has an upper edge — its own centreline pushed out along its own normal by half the thickness. Those two edges cross at one point.

A join vector is correct when it lands on that crossing, and the condition for that is startlingly simple. Measured in half-thicknesses, the join must have unit projection onto each normal:

dot(join, normalLeft)  == 1
dot(join, normalRight) == 1

Not length 1 — projection 1. That single line explains every 1./dot(...) in the file. Each one is solving this equation for a particular assumed direction.

normalLeftnormalRightoffset edges

The crossing ✕ is the target. Plates 06–09 are four different guesses at how to reach it — or at when to deliberately miss.

PLATE 06

Guess one: the bisector, and its price

Add the two unit normals and renormalise — you get the angle bisector. Assume the join points that way, and solve dot(join, nL) = 1:

vec2 bisec =
  normalize(normalLeft + normalRight);
float bisecLen =
  abs(1. / dot(normalLeft, bisec));
join = bisec * bisecLen;

Because the bisector sits at half the corner angle from each normal, dot(nL, bisec) = cos(θ/2) and so bisecLen = 1/cos(θ/2). This is the textbook miter, and it is exactly what line-vert.glsl does — unconditionally, with no branch at all.

It is also a trap. As the corner sharpens, θ → 180°, cos(θ/2) → 0, and the miter length runs to infinity. A loud transient in the audio does precisely this, and the line grows a spike taller than the plot.

Inset: 1/cos(θ/2). At this vertex θ ≈ 87°, so bisecLen ≈ 1.44 — mild. The asymptote is the problem the rest of the shader exists to dodge.

PLATE 07

The ruler: everything is half-thicknesses

Look at how join is spent, five lines from the end:

position += sign * join
   * .5 * thickness / viewport.zw;

join is dimensionless. A join of length 1 displaces exactly half a line thickness; sign = ±1 makes the two edges, so a unit join yields a line exactly thickness wide. That is the unit for every number in the branch.

Now guess two — travel straight up instead of along the normal, and solve the same equation. With vert = (0,1):

float vertLeftLen =
  abs(1. / dot(normalLeft,  vert));
float vertRightLen =
  abs(1. / dot(normalRight, vert));

Since dot(n, vert) = n.y, this is 1/|n.y| — the hypotenuse over the run. It answers: how far up must I go to still sit on that edge? Always ≥ 1, and it blows up as the segment goes vertical, just like the miter does.

Left: the ruler. Right: the vertical route costs vertLen where the perpendicular route costs 1.

PLATE 08

Putting σ on the same ruler

The one conversion that makes the branch readable:

float vertSdev =
  2. * sdev * viewport.w / thickness;

Run it forward through the ruler. A vertical join of that length displaces

vertSdev * .5*thickness/viewport.w
   ==  sdev

…exactly. With sign = ±1 the ribbon spans precisely ±1σ. So vertSdev is not a fudge factor or a tuning constant — it is σ re-expressed in half-thicknesses, so that a data quantity can be compared against the geometric ones from Plate 07.

vertSdev < 1 means the spread of the samples in this column is narrower than the line is thick — drawing it would be invisible. vertSdev > 1 means the signal genuinely needs more vertical room than the line already gives it.

The comment says “2σ covers 68%”. Read as ±1σ from the centre, which is what the code does, that is the usual 68%.

PLATE 09 · INTERACTIVE

The branch is one continuous curve

Three quantities, all in half-thicknesses: vertSdev, and the two gates minVertLen / maxVertLen. The branch is just where σ falls between them:

if (vertSdev < maxVertLen) {
  if (vertSdev > minVertLen) {
    float t = (vertSdev - minVertLen)
        / (maxVertLen - minVertLen);
    join = lerp(bisec*bisecLen,
                vert*maxVertLen, t);
  }
  else join = bisec * bisecLen;
}
else join = vert * vertSdev;

Drag σ and watch the join vectors. Below the first gate it is a pure miter and σ is invisible. Above the second it is pure vertical and geometry is discarded — the ribbon simply becomes the ±1σ envelope. Between them it rotates.

Check the seams. At t = 0 the lerp returns bisec*bisecLen; at t = 1 it returns vert*maxVertLen, which is what the third branch gives at that instant. The function is continuous. The blend band is not a third mode — it is the hinge that stops the other two from popping.

Each vertex has its own gates, from its own two normals, so neighbours switch at different σ. That is why the ribbon flares unevenly.

Number line is for the spotlight vertex ◆ only. Ribbon vertices are tinted by the branch each one takes. End vertices use the NaN caps — join = normalRight / normalLeft, one lone normal, no corner to solve.

PLATE 10

Spend it, shift it, project it

position += sign * join
   * .5*thickness / viewport.zw;

position.x += passId * pxStep
   * samples.length / sampleStep
   / viewport.z;

gl_Position =
  vec4(position * 2. - 1., 0, 1);

Note viewport.zw, not .ww. Both components of join · ½·thickness are pixel distances; each is normalised by its own axis. The normal was built isotropically in Plate 04 and it is unbuilt isotropically here — the aspect correction is symmetric, so a 45° join still looks like 45° on screen.

The passId line tiles fixed-size texture passes side by side. Then × 2 − 1 maps the 0…1 box onto clip space, and the vertex is done.

Everything upstream ran in 0…1 normalised space on purpose: it is the only space where a y from deamp and an x from pxStep are directly comparable. Clip space is put on last, as a coat.

Two vertices, one id, sign = ±1 — pushed apart, then remapped.

Edges to the reading

correction

“Miter” is not a horizontal mode

It is the genuine geometric bisector and it can point anywhere in that −90°…+90° fan. For a gentle waveform it sits close to vertical; it only swings toward horizontal when the corner is sharp. The mode names describe the rule used, not a direction.

the missing half

Two jobs, one vector

Snapping to vertical caps the miter spike — but that is the side effect. The purpose is that this shader draws an aggregate, and the vertical join is literally the ±1σ envelope of the samples in that column. Plain line-vert.glsl plots single samples, has no σ, and needs none of this.

nuance

The gates are min and max, not left and right

minVertLen/maxVertLen are a sorted pair, so the shader never cares which side was steeper. The blend always ends at vert * maxVertLen — the looser of the two — which is what makes the handoff to the vertical branch exact.

nuance

The end caps are not the corner rule

The first two branches fire on statsPrev.z == -1 / statsNext.z == -1 — the NaN flag, meaning there is no neighbour. They fall back to a single raw normal, ignoring σ entirely. Those are data-boundary cases, not shape cases.

caveat in the source

Only the current σ is used

sdevPrev, sdevNext and friends are computed, normalised, and then only shipped to the fragment shader as varyings. The join reads sdevCurr alone — which is what the author's own // FIXME: sdev should be compensated by curve bend is about.

caveat

The vertical branch is unbounded

join = vert * vertSdev has no ceiling. On very noisy data the ribbon can reach well past the plot. The miter spike was traded for a vertical one — far less objectionable for a waveform, but not eliminated.

discrepancy

The two shaders normalise differently

range-vert uses vec2(-dy, pxStep/viewport.w) — both terms in viewport-heights. line-vert writes vec2(-dy, pxStep/viewport.z) / viewport.zw, which divides the amplitude delta by width. Worth knowing before you read one as a simplification of the other.

context

side earns its keep downstream

It never moves a vertex, but statsLeft/statsRight/statsPrevRight/statsNextLeft let fade-frag.glsl know which two centrelines a fragment sits between — that is where the antialiasing and the alpha falloff come from.
